# Notification reliability scope

Improve existing notifications without changing business permissions, company ownership, receipt workflows, or native dependencies. Preserve notification preferences, maintenance reminders off by default, and existing timesheet reminder times: Sunday 18:00, Monday 08:00 and 12:00. Use Europe/London for server business schedules, with daylight-saving tests; preserve existing device-local maintenance time until an explicit preference migration is implemented.

Confirmed: remote inbox normalization only stamps recipients for bookings, holidays and timesheet reminders; general and maintenance records consequently fail the account visibility check. The mobile API also drops ownership from returned notification envelopes. General server notification creation writes an inbox record but does not send push. Timesheet scheduling watches one week selected when the effect starts. Push registration runs on login/account changes; foreground currently reconciles the inbox only.

Required outcomes: account-scoped inbox visibility; durable server delivery with duplicate protection, retries, provider receipts and stale-token cleanup; correct rollover and cancellation for timesheet reminders; existing preference enforcement; useful delivery diagnostics; staged backend-first rollout followed by OTA for both platforms. Do not replay historical push notifications. Do not promise physical device delivery based on automated tests or provider acceptance alone.

Deployment constraints: use independently reviewed changes based on each current production source, never the heavily modified working checkout. Keep runtime 5.0.12 and current native configuration. Verify the live hosted scheduler and its authentication before selecting the queue host; do not rely on an in-process timer on the sleeping mobile API instance. Keep receipts' existing delivery implementation unchanged. Preserve the Booking project's Project Control records and release gates. Record actual device-test limitations and provide a rollback switch per migrated notification type.
